# v0.3.0 V3-16 Gameplay, Tray, Controls, and Motion Implementation Notes

Date: 2026-10-07 (Asia/Kolkata)

## Scope completed

- Replaced the baseline gameplay surface with the approved autumn composition at 360 x 800, 390 x 844, 412 x 915, and 430 x 932.
- Kept the board, tray, assist counts, score progress, Special Concentration uses, feedback, and completion navigation bound to the existing engine and persisted offline state.
- Added density-aware board geometry for 36-, 72-, and 144-tile layouts. Tile size and spacing reduce deterministically while the six-column layered layout remains inside the gameplay frame.
- Added explicit covered and side-blocked causes without changing the existing availability rule. The cause is communicated through both tile treatment and accessibility labels.
- Rebuilt the tray as four persistent regular pockets plus one separate Identity/Special Concentration pocket. Selected tiles occupy stable slot positions and compact after removal.
- Added board-to-tray entry, pair removal, Undo restoration, Shuffle relayout, Hint pulse, and newly exposed tile feedback. Reduced Motion removes nonessential travel and pulse while preserving state changes.
- Replaced the former Restart dock action with the approved More control. Restart remains in the top bar; V3-17 owns confirmation, Pause, More, No Moves, and Full Tray overlays.
- Extracted the approved Back, Restart, and Identity emblem artwork through a reproducible script and generated registry.
- Removed the confirmed-unused `gameplay-screen 2.tsx` duplicate after route and import checks proved that only `gameplay-screen.tsx` is reachable. Other cleanup-ledger entries remain untouched for V3-20.

## Runtime state mapping

| Presentation value                    | Runtime authority                                           |
| ------------------------------------- | ----------------------------------------------------------- |
| Board tiles and availability          | `activeRun.session.game` and the existing availability rule |
| Regular tray                          | `activeRun.session.regularTray`                             |
| Identity/Special uses                 | `activeRun.session.specialUsesRemaining`                    |
| Undo, Hint, Shuffle counts            | Local economy ledger balances                               |
| Base Zen progress                     | `getZenScoreBase(session.assistUsage)`                      |
| Reduced Motion                        | Persisted application settings                              |
| Pair, blocked, failed, and won states | Concentration engine events and session status              |
| Foreground/background timing          | Existing AppState timing lifecycle in `AppDataProvider`     |

## Assumptions and decision gates

- D-11 is validated at the renderer level: temporary QA specimens confirmed 36-, 72-, and 144-tile containment. The specimen route was removed after inspection and is not part of the product.
- D-12 remains open. The visible artwork says `Identity`, matching the approved design, while engine behavior and accessibility retain `Special Concentration` semantics.
- D-17 remains release-blocking. Numbered gameplay still creates the documented deterministic 36-tile `garden-two` presentation fixture because the production level-to-board-size schedule and conforming Special artwork are not approved. V3-16 does not disguise the fixture as completed level generation.
- The rule-authoritative Zen milestones remain 3, 6, 10, and 20 even though an older design label showed 3, 10, 15, and 20.
- Full More and Restart confirmation behavior is intentionally deferred to V3-17. The More control temporarily preserves access to the existing rewarded-assist modal; existing recovery presentation remains functional but is not claimed as design-conformant in this milestone.
- Exact production artwork is used where V3-13 marked it ready. Catalogue/artwork mismatches documented in V3-13 remain unresolved and are not replaced with invented final art.
- Physical 60 FPS, memory, thermal, and touch review remains V3-21 release QA. V3-16 verifies deterministic geometry, interaction behavior, exports, and responsive rendering locally.
