# v0.3.0 V3-5 Inventory and Local Ledger Implementation Notes

## Scope

Milestone V3-5 implements the offline assist inventory, append-only local economy ledger, deterministic Hint, solvability-preserving Shuffle, transactional Undo, revival spending integration, and confirmed automatic achievement rewards.

This is a new v0.3.0 implementation record. Earlier-version documents remain unchanged.

## Ledger authority

- Balances are derived from immutable ledger entries rather than stored as independently editable counters.
- Entries are grouped into immutable transactions with stable caller-supplied transaction IDs.
- Replaying a transaction ID has no additional effect.
- A transaction is rejected atomically when its final balance would be negative.
- Undo appends compensating entries. It never deletes or rewrites the original transaction.
- Every entry belongs to exactly one transaction, and persisted JSON can be validated before balances are reconstructed.

The first-install transaction grants exactly:

| Assist  | Quantity |
| ------- | -------: |
| Shuffle |        2 |
| Undo    |        4 |
| Hint    |        6 |

The fixed `initial-assist-grant:v0.3.0` transaction can be ensured repeatedly against an existing ledger without resetting or duplicating consumed balances.

## Hint

Hint returns a deterministic valid command:

1. Prefer an available board match for a tile already in the regular tray.
2. When a full tray is recoverable, identify the corresponding special-slot command.
3. Otherwise identify the first deterministic available board pair and return the first selection plus its follow-up tile.

Hint inventory is consumed only when a valid hint exists. Retrying the same transaction ID does not consume another Hint.

## Shuffle

Shuffle preserves the set of remaining board positions and tile identities. It deterministically assigns active tiles to a one-at-a-time removal order derived from the session seed and Shuffle count.

Before charging inventory, the engine replays a complete Concentration command sequence from the shuffled state to `won`. The replay includes existing tray entries and special-slot recovery when a full tray has that capability. If no validated route exists, Shuffle is rejected without a ledger entry.

## Transactional Undo

Accepted gameplay mutations are recorded with complete before-and-after session snapshots and any associated economy transaction. Undo:

1. Restores the latest gameplay snapshot.
2. Compensates that transaction's economy entries when applicable.
3. Charges one Undo in the same atomic ledger transaction.
4. Preserves later non-gameplay assist usage, such as a Hint requested after the move.

Hint is advisory and is not itself an Undo target. Shuffle, revival, selection, special-slot use, and Restart can be Undo targets when executed through the tracked command coordinator.

## Achievement rewards

Confirmed streak rewards are implemented at days 7, 14, and 21. Confirmed Concentration Score rewards are implemented at 25, 50, 100, 125, 150, and 200.

- Rewards are automatic when eligibility evaluation runs.
- Each achievement uses a fixed transaction ID and is granted once.
- Concentration Score awarded by an achievement does not recursively unlock another threshold in the same evaluation.
- Threshold behavior after 200 remains deferred.

## V3-5 implementation boundaries

- V3-6 will connect completion scoring and tier Concentration Score to ledger transactions.
- V3-7 will persist and migrate the economy ledger, command history, and active run atomically.
- V3-8 will connect the domain assists to production controls and feedback.
- Advertisement and purchase grants remain outside this milestone.
- Restart cost remains unresolved and therefore has no ledger mutation.

## Verification

- Initial grant and repeated ensure behavior.
- Transaction replay, insufficient balance, and JSON reconstruction.
- Compensation without deleting historical entries.
- Deterministic Hint with no duplicate charge.
- Deterministic Shuffle with complete solution replay for empty, partial, and full trays.
- No Shuffle charge when recovery is impossible.
- Undo of selection, Shuffle, and revival with correct balance restoration.
- Automatic once-only achievement rewards and non-recursive score evaluation.
