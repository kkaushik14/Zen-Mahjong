# v0.3.0 V3-4 Concentration Engine Implementation Notes

## Scope

Milestone V3-4 implements the framework-independent Concentration Tray state machine. It does not add production UI, inventory ledgers, advertisement recovery, purchases, or final persistence migration.

This is a new v0.3.0 implementation record. Earlier-version documents remain unchanged.

## Implemented commands

- `select-board-tile` moves one available board tile into the first open regular tray position.
- `use-special-slot` resolves one tray tile with an available matching board tile.
- `restart` restores the level's initial board and gameplay counters.
- `revive` spends the quoted Concentration Score and returns unresolved tray tiles to the board.

Every command returns a new session and domain events when accepted. A rejected command returns the original session reference, no events, and a typed rejection reason.

## Tray and status rules

- The regular tray contains four ordered tile-instance IDs.
- Inserting a matching identity resolves both entries immediately.
- Remaining tray entries retain their relative order.
- A level is won only when the board and regular tray are both empty.
- A full unmatched tray is `blocked` when a remaining special-slot use can reach a matching available board tile.
- A full unmatched tray is `failed` when that recovery is not currently possible.
- A non-full session also fails when no board tile is available and the level is not complete.

## Special slot

The special slot is represented as one atomic command rather than a separately persisted animation phase. The command:

1. Verifies that the tile occupies the regular tray.
2. Verifies that one category-specific use remains.
3. Finds the first matching board tile that is currently available.
4. Resolves the pair, compacts the tray, and decrements the use count.

Rejected special-slot commands never consume a use.

## V3-4 implementation assumptions

### Revival behavior

Revival returns all unresolved regular-tray tiles to their existing board positions. Pairs resolved before failure remain resolved. Revival clears the tray, increments the attempt's revival count, and uses the confirmed `10, 15, 25, 40...` price sequence. V3-5 will record the accepted cost in the local ledger.

### Restart boundary

Restart restores the initial board, clears the tray, resets revival count, and restores the category's included special uses. It currently preserves timing and assist-usage fields because Restart cost, timer treatment, and economy rollback remain unresolved or belong to later milestones.

### Atomic transitions

Pair resolution and special-slot resolution are atomic domain transitions. Presentation may animate intermediate movement later, but persistence receives a complete accepted state rather than a half-resolved pair.

- Unavailable board-tile rejection.
