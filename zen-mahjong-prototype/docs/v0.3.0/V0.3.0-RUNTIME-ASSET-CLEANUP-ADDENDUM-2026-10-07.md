# v0.3.0 Runtime Asset Cleanup Addendum

Date: 2026-10-07 (Asia/Kolkata)

## Purpose

This addendum extends the [v0.3.0 Design-Conformance Execution Plan](V0.3.0-DESIGN-CONFORMANCE-EXECUTION-PLAN-2026-10-07.md).

After the approved screens, shared components, tile artwork, and Moonlit Garden visual system are integrated, obsolete assets must be removed from runtime build inputs and regenerated build output. Cleanup happens before final device and release QA.

## Added milestone: V3-20A Runtime Asset Pruning

V3-20A runs after V3-20 end-to-end integration and before V3-21 release QA.

```text
V3-20 End-to-end integration
  -> V3-20A Runtime asset pruning
  -> V3-21 Release QA
```

## Cleanup scope

### Remove when confirmed unused

- Superseded V2 runtime artwork replaced by approved Moonlit Garden assets.
- Expo starter imagery that is no longer referenced, such as unused React logos, Expo badges, tutorial placeholders, or sample tab icons.
- Old screen-sized images that were used as temporary mockups instead of composable runtime assets.
- Duplicate exports of the same approved asset.
- Temporary review images accidentally copied into application asset directories.
- Obsolete generated bundles and cached build copies containing removed assets.
- Unused font files after the approved font and fallback set is finalized.
- Stale suffixed source copies after import and test verification proves that they are unused.

### Preserve

- App icon, adaptive Android icon, monochrome icon, favicon, and splash assets that remain referenced by Expo configuration.
- Every production runtime asset referenced by the final asset registry.
- Source artwork and editable masters used to regenerate runtime assets.
- The frozen Figma baseline under `docs/v0.3.0/design-baseline/2026-10-07/`.
- Versioned documentation, review evidence, checksums, manifests, and generated master sheets.
- Assets required to restore historical local sessions or resolve retired catalogue entries.
- User-created files and unrelated workspace content.

The frozen design export is evidence and source material, not application build input. It must not be deleted as part of runtime cleanup.

## Required procedure

1. Finish all approved screen and component integration.
2. Build a runtime asset inventory containing asset path, owner, source node or catalogue ID, importing modules, platform use, and readiness status.
3. Search static imports, Expo configuration, CSS, JSON catalogues, tests, scripts, and asset registries for every deletion candidate.
4. Check for dynamic asset lookup conventions that cannot be found by a simple import search.
5. Mark an asset obsolete only when an approved replacement exists and every runtime reference has migrated.
6. Remove obsolete source assets with a focused `apply_patch` change. Do not use broad wildcard deletion.
7. Clear generated build output and caches so old packaged assets cannot survive from an earlier build.
8. Regenerate iOS, Android, and web bundles from the cleaned runtime source.
9. Inspect generated asset manifests and bundles for removed filenames, duplicate hashes, unexpected review images, and unreferenced large files.
10. Launch and exercise every approved screen offline on iOS and Android before accepting the cleanup.

## Generated output policy

- Generated build directories must not be treated as the authoritative asset source.
- Do not manually edit generated native projects or packaged asset manifests to hide an obsolete asset.
- Delete or regenerate disposable output through the repository's normal Expo, EAS, Metro, Xcode, Android, and web build workflows.
- A clean build must succeed without relying on files left in a previous cache.
- Cleanup must not remove a native file that is generated from current Expo configuration; change the source configuration or runtime import instead.

## Verification gates

- [ ] Every approved screen and component uses the final asset registry.
- [ ] All runtime asset imports and dynamic lookups resolve.
- [ ] Expo icon and splash configuration resolves on both platforms.
- [ ] No runtime code imports from `docs/`, Downloads, temporary folders, or Figma review exports.
- [ ] No superseded V2 visual asset remains in the final bundle unless an explicit approved screen still requires it.
- [ ] No full-screen Figma screenshot is shipped as an application screen.
- [ ] No source sheet, checkerboard, caption, or review background appears in runtime UI.
- [ ] Duplicate binary hashes are reviewed and intentional duplicates documented.
- [ ] iOS, Android, and web bundles are regenerated from a clean state.
- [ ] Offline launch, all approved routes, all overlays, and historical-session restoration work after cleanup.
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm test`, and `pnpm format:check` pass.
- [ ] Expo Doctor passes in the supported Node 24 environment.
- [ ] Final release notes list removed assets, retained exceptions, and bundle-size change.

## Exit criteria

V3-20A is complete only when:

1. The application builds and launches from a clean environment without an old asset cache.
2. Every approved screen, popup, tile, icon, and font renders from an intentional runtime source.
3. Removed assets do not appear in generated bundle manifests or packaged application resources.
4. The frozen design baseline and regeneration sources remain available.
5. V3-21 device and release QA can run against the cleaned release candidate.
