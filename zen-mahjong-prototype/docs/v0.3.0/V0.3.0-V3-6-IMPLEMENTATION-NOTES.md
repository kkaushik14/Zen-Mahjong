# v0.3.0 V3-6 Score, Timing, and Progression Implementation Notes

## Scope

Milestone V3-6 implements foreground-active timing, Zen Score completion receipts, score presentation milestones, incremental level progression, eight-level Concentration Score awards, device-date streak progression, and automatic threshold reward evaluation.

This is a new v0.3.0 implementation record. Earlier-version documents remain unchanged.

## Foreground timing

- A numbered session starts timing from `startedAt` unless it is explicitly created paused.
- Moving to the background pauses the timer and stores accumulated milliseconds.
- Returning to the foreground resumes from the saved duration.
- Winning and failed sessions cannot resume timing.
- Completion pauses at the supplied final-match timestamp.
- Negative elapsed time caused by a backward device-clock change is clamped to zero rather than reducing accumulated play time.

Active milliseconds are retained in the session. Completion receipts store whole elapsed seconds using floor. The UI does not need to display the timer during gameplay.

App lifecycle wiring is deferred to the presentation milestone, but the lifecycle operations are framework-independent and fully tested.

## Zen Score

Completion uses the authoritative eight-row assist precedence table. It then adds:

- `+1` when the level is at least ten seconds faster than the immediately previous completed numbered level.
- `+1` for every qualifying assist advertisement result supplied to completion.

The first completed level has no comparison bonus. There is no advertisement bonus maximum in the domain model.

Every accepted completion stores a versioned receipt containing active duration, assist usage, advertisement count, final Zen Score, session ID, level number, and completion timestamp.

## Score presentation

The confirmed percentages are represented as stepped presentation milestones rather than an invented linear formula:

| Zen Score |                               Milestone state |
| --------: | --------------------------------------------: |
|       0-2 |                                            0% |
|       3-5 |                                           10% |
|       6-9 |                                           20% |
|     10-19 |                                           50% |
|        20 |                       Standard-scale endpoint |
|  Above 20 | Endpoint plus overflow state and actual score |

The final UI can render the score-20 endpoint as visually "almost full" while preserving the separate overflow treatment.

## Incremental progression

- The next accepted receipt must match `currentLevelNumber`.
- Acceptance increments the current level by one.
- A repeated receipt ID is idempotently rejected.
- A different receipt for an already completed level is rejected as replay.
- No replay action is represented in the progression contract.

Restored progression validation requires sequential receipts beginning at level 1.

## Tier Concentration Score

- No partial tier awards Concentration Score.
- Completing the eighth sequential level calculates the tier average.
- Fractional values through exactly `.5` round down; values above `.5` round up.
- The award is appended to the local economy ledger with a deterministic tier transaction ID.
- Tier records must cover the exact eight levels and sum to lifetime earned Concentration Score.

Concentration Score achievement eligibility uses lifetime earned tier score rather than the spendable current balance. This prevents revival spending from erasing achievement progress.

## Streak

- The first device-local visit is day 1.
- The next calendar date increments the streak.
- A gap resets the current streak to day 1 while preserving the best streak.
- Repeated visits on one date do not increment it.
- Earlier dates caused by clock rollback do not move progression backward.

The caller supplies the device-local `YYYY-MM-DD` date so the domain remains independent of platform time-zone APIs.

## V3-6 implementation boundaries

- Production advertisement qualification remains deferred to V3-9.
- App background and foreground events will call the timing operations in V3-8.
- Atomic persistence and recovery of receipts, progression, timing, and ledger transactions belong to V3-7.
- Tutorial and practice remain isolated from this numbered progression aggregate.

## Verification

- All eight base-score combinations.
- First completion, exactly ten seconds faster, and less-than-ten-second behavior.
- Unlimited qualifying ad bonuses and scores above 20.
- Foreground pause and resume with background time excluded.
- Strict sequential completion, duplicate receipt, and replay rejection.
- No partial-tier award and exactly `.5` rounding down.
- Tier ledger award and once-only score achievement reward.
- Streak continuation, same-day idempotency, and gap reset.
- JSON reconstruction and progression invariant validation.
