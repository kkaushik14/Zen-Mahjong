# v0.3.0 V3-18 Implementation Notes

## Scope

V3-18 implements the approved Profile, Edit Profile, Settings, and Appearance surfaces using device-local state. It does not add authentication, account switching, cloud actions, purchases, notifications, or a theme store.

## Profile

- Profile uses the approved cool-garden backdrop, bonsai emblem, ivory material, and moonlit navigation control.
- Boards completed, current streak, and best streak come from the v0.3.0 offline progression aggregate. Daily challenges remains the existing local counter and is not presented as a playable destination.
- Edit Profile is a self-contained modal. The garden name is trimmed, repeated whitespace is collapsed, blank values are rejected, and the result is persisted in the existing local player repository.
- The editor uses a controlled text input, keyboard avoidance, platform back dismissal, explicit Save and Cancel actions, and Reduced Motion-aware presentation.

## Settings and Appearance

- Reduced Motion remains the only user-facing toggle because it already changes loading, board, and overlay behavior throughout the application.
- The approved `Autumn garden · Ivory marble` atmosphere is the only available local appearance. Applying it persists `tileStyle: ivory-marble`; no unapproved themes, store, or remote catalogue were added.
- The settings repository advances from schema version 2 to 3 and migrates the legacy `classic` tile-style value to `ivory-marble`. Existing schema-one settings still migrate sequentially through schema two.
- The screen uses a fixed 16-point phone gutter and a vertical scroll container, covering the approved 360, 390, 412, and 430 widths without horizontal overflow.

## Intentionally Gated

- Music, ambient sound, and sound effects remain hidden under D-05 because no approved audio content or playback service exists.
- Daily reminder remains hidden under D-06 because notification permission, schedule, and copy are undecided.
- Haptics, auto hints, high contrast, consent preferences, restore purchases, support destinations, authentication, and cloud controls are not presented as functional until their behavior and designs are approved.
