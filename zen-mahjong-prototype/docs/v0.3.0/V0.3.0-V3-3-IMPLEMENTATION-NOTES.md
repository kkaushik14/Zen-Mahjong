# v0.3.0 V3-3 Level and Tier Implementation Notes

## Scope

Milestone V3-3 implements deterministic tier mapping, level definitions, 36-, 72-, and 144-tile board generation, catalogue validation, and executable solution evidence. It does not implement the Concentration Tray state machine, assist consumption, final production layouts, or special-tile artwork.

This is a new v0.3.0 implementation record. Earlier-version documents remain unchanged.

## Confirmed behavior represented in code

- Every tier contains eight incrementally numbered levels.
- Category order is Normal, Normal, High, High, Super, Super, Special, Special.
- A level records its seed, content version, board size, category, tier position, assist contract, and tile-design sequence.
- Identical input and content versions produce identical level definitions, board geometry, tile instance IDs, and solution evidence.
- An assist requirement is removed when that assist is not available to the offline player.
- Every generated board includes solution steps that are replayed through the gameplay availability and matching rules before the board is accepted.
- Special Concentration selects four approved special designs and refuses generation when the approved pool is incomplete.

## V3-3 implementation assumptions

### Board-size assignment

The engine supports 36, 72, and 144 tiles, but it does not assign a size to a numbered level. Board size is an explicit content input so a later content review can choose the progression without changing engine rules.

### Solvable geometry

Generated boards currently use six-column layered rows:

| Board size | Rows by layer, base to top |
| ---------: | -------------------------- |
|         36 | `4, 2`                     |
|         72 | `6, 4, 2`                  |
|        144 | `12, 8, 4`                 |

Solution evidence removes upper layers before lower layers and removes each row from its open edges inward. This geometry is a deterministic validation fixture, not final visual level design.

### Difficulty profile

Until reviewed similar-tile families exist, category difficulty increases catalogue variety:

| Category |                                       First level |                                      Second level |
| -------- | ------------------------------------------------: | ------------------------------------------------: |
| Normal   |                                         4 designs |                                         5 designs |
| High     |                                         6 designs |                                         7 designs |
| Super    |                                         8 designs |                                         9 designs |
| Special  | 9 regular designs plus 4 selected special designs | 9 regular designs plus 4 selected special designs |

Similarity-based difficulty becomes active when approved catalogue entries share a `similarityGroup` while retaining different `matchIdentity` values.

### Assist-required content

V3-3 can store an explicitly requested assist requirement, but it does not choose one automatically. If the requested assist is absent, the generated offline definition has no assist requirement. Reservation, consumption, and restoration semantics remain deferred to the inventory and Concentration milestones.

## Production gate

The bundled v0.3.0 catalogue intentionally contains no placeholder special designs. Levels 7 and 8 therefore require a future reviewed catalogue containing at least four approved, eligible special designs. Tests use synthetic special entries only to verify the generation contract.

## Verification

- Generate all three supported board sizes.
- Reproduce a level exactly from the same seed and content version.
- Replay every recorded solution step through engine matching and availability rules.
- Reject tampered evidence and invalid catalogue references.
- Generate a complete synthetic eight-level tier in the confirmed category order.
- Verify unavailable offline assists cannot become required by the saved level contract.
