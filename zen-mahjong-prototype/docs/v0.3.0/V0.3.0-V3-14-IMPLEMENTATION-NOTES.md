# v0.3.0 V3-14 Implementation Notes

Date: 2026-10-07 (Asia/Kolkata)

## Scope completed

- Extracted 18 reusable Moonlit component assets from the frozen design handoff with a reproducible generator and manifest.
- Rebuilt shared buttons, gameplay action controls, balance/status treatments, Zen progress, settings rows, switches, modal framing, textured surfaces, and the application safe-area/background wrapper.
- Applied the approved marble face to Mahjong tiles and the approved wood pocket to the Concentration tray.
- Preserved native, data-driven text and values above decorative imagery.
- Added default, pressed, disabled, zero-balance, selected, hinted, loading, and Reduced Motion behavior at the appropriate component boundaries.
- Kept practical touch targets through minimum dimensions and hit slop.
- Added a source-only component specimen and removed its public route and settings navigation entry.
- Removed stale `apps/mobile/ios/build` and `apps/mobile/dist-web` outputs so old bundled assets cannot be mistaken for the V3-14 runtime set.
- Added focused interaction and accessibility coverage for the new shared contracts.

## Visual QA

The frozen component masters and browser-rendered specimens were reviewed at phone and tablet-width constraints. The first render found an over-stretched wide frame and a duplicate nested switch accessibility target. The wide control is now capped to the approved 364-point working width, and a settings row exposes exactly one switch target while reusing noninteractive switch artwork.

The lower specimen review found settings trailing content and a popup shell expanding beyond the intended tablet composition. Settings surfaces now explicitly contain their full row width and popup shells cap at 520 points.

The three-piece wide frame includes intentional transparent artwork above parts of the marble surface; native labels remain layered over the composed frame and are not rasterized into the asset.

## Assumptions and deferred decisions

- The frozen 2026-10-07 export is the visual authority for V3-14 because live Figma file access was unavailable during implementation.
- `ModalShell` owns reusable presentation only; overlay behavior, dismissal policy, recovery variants, and game-state bindings remain V3-17 work.
- `AppScreen` supplies composition-safe background rendering but does not decide which product screen uses which approved background; each screen milestone owns that choice.
- The existing Special Concentration engine terminology is preserved until the Identity/Special wording decision is finalized in V3-16.
- No rule, scoring, persistence, inventory, or matching behavior was changed by this milestone.
