## Overlay state authority

| Overlay     | Visibility authority                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| Restart     | Explicit top-bar or Pause action                                             |
| Pause       | Explicit gameplay back/pause action                                          |
| More        | Explicit dock More action                                                    |
| Full Tray   | Engine status `blocked`, or `failed` with four regular tray tiles            |
| No Moves    | Engine status `failed` with fewer than four regular tray tiles               |
| Rewarded ad | Only when the configured provider reports the relevant placement available   |
| Paid Revive | Only when the local Concentration Score balance covers the next revival cost |

## D-07 resolution

The rejected generic concept “no legal pairs remain” is not used. `No Moves` is reserved for an engine-derived failed arrangement with an unfilled tray, and its rule-safe copy is: “This arrangement cannot continue.” A full tray always uses the separate Full Tray recovery state.

## Recovery behavior

- A blocked Full Tray offers `Choose Tray Tile`, then returns focus and input to the real tray so the player can spend one Identity/Special use.
- A failed Full Tray conditionally offers the next score-funded Revive and/or rewarded Revive, followed by Restart and Save & Home.
- No Moves conditionally offers Shuffle when inventory is available, followed by Restart and Save & Home.
- Revival cost is calculated with `getRevivalCost(session.revivalCount + 1)`; no fixed cost is embedded in presentation code.
- Reward actions remain hidden when their advertisement placement is unavailable.
- Save & Home pauses and persists the current run. Re-entering gameplay resumes that same run.

## Assumptions and design differences

- The approved Full Tray still image contains only Restart and Save & Home. Runtime rules require Identity/Special, score-funded Revive, and rewarded Revive paths, so the action stack is state-derived and may be taller than the still image. The approved frame, typography, spacing, and button language are preserved.
- The approved More image has three actions. `Earn an Assist` appears only when the configured advertisement provider reports the assist placement available; it is absent in production configurations that do not provide the placement.
- Recovery-overlay backdrop or native back dismissal uses Save & Home because recovery cannot be dismissed into an invalid playable state. Pause, More, and Restart dismissal resumes the current run.
- Native focus is moved to the modal boundary after presentation. Web skips the unsupported native `findNodeHandle` path and retains normal document focus behavior.
- Physical iOS and Android screen-reader, hardware-back, and gesture sign-off remains part of the final device/release QA milestone. The contracts are implemented and local browser interaction is complete.
