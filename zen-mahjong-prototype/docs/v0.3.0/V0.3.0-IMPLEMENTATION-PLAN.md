# v0.3.0 Offline Implementation Plan

## Scope boundary

This plan implements the offline-complete mobile experience. It does not implement backend services, OAuth, production cloud synchronization, cloud retention enforcement, or production advertisement verification.

## Milestone V3-1: Executable specifications

- Convert decisions into typed schemas and table-driven fixtures.
- Add score, revival, tier, inventory, and streak examples.
- Add schema versions for catalogue, level, active session, ledger, and completion receipt.

Exit: every implemented transition cites a versioned rule and has at least one acceptance example.

## Milestone V3-2: Tile catalogue and master sheet

- Add the authoritative machine-readable catalogue.
- Implement same, similar, regular, and special classifications.
- Generate a reviewable master sheet from catalogue data.
- Add validation for duplicate IDs, missing pairs, inaccessible labels, and retired content.

Exit: engine, UI, tests, and master sheet resolve tile identity from one source.

## Milestone V3-3: Level and tier system

- Implement deterministic eight-level tiers and incremental numbering.
- Add Normal, High, Super, and Special configuration.
- Build seeded 36-, 72-, and 144-tile content generation.
- Add a validator and solution evidence.

Exit: generated content is reproducible and satisfies its declared difficulty and assist contract.

## Milestone V3-4: Concentration engine

- Add four ordered regular tray slots and one special slot.
- Add automatic pair resolution, compaction, blocked state, failure, Restart, and revival.
- Add special-use counters by category.
- Keep transitions pure and framework-independent.

Exit: command tests cover every slot, pair, failure, recovery, and invalid transition.

## Milestone V3-5: Inventory and local ledger

- Add initial inventory of 2 Shuffle, 4 Undo, and 6 Hint.
- Add deterministic Hint, solvability-preserving Shuffle, and transactional Undo.
- Add append-only local balance entries and idempotent receipts.
- Add automatic once-only achievement rewards.

Exit: retries, reloads, and Undo cannot duplicate or lose inventory.

## Milestone V3-6: Score, timing, and progression

- Implement the eight-row precedence table.
- Track foreground active time and the faster-completion bonus.
- Add unlimited score range and the visual overflow state.
- Calculate tier Concentration Score with the confirmed rounding rule.
- Add incremental progression with no replay action.

Exit: boundary tests cover every score case, exactly 10 seconds, exactly `.5`, score above 20, and tier completion.

## Milestone V3-7: Persistence and migration

- Add versioned documents for tray sessions, inventory, ledger, achievements, timing, and tier progress.
- Preserve or explicitly migrate legacy two-selection sessions.
- Add previous-snapshot recovery and corruption fallback.
- Add a future-sync outbox contract without a network implementation.

Exit: termination at every critical transition restores one internally consistent state.

## Milestone V3-8: Tutorial and presentation

- Build tutorial and practice sessions.
- Build tray, blocked recovery, score, overflow, tier, streak, and achievement presentation.
- Add phone and tablet layouts, screen-reader order, and Reduced Motion variants.
- Verify updated designs before visual sign-off.

Exit: a new player can complete tutorial, practice, and one full tier without external instructions.

## Milestone V3-9: Advertisement adapter

- Add an advertisement provider port and deterministic fake provider.
- Add assist and revival result types.
- Add local idempotency receipts.
- Keep gameplay complete when the provider is unavailable.

Exit: advertisement UI can be tested without a production SDK or server.

## Milestone V3-10: Device and release QA

- Run unit, property, integration, migration, and accessibility tests.
- Validate 36-, 72-, and 144-tile behavior.
- Measure 60 FPS, launch, resume, memory, and battery targets.
- Complete physical iOS and Android runs, including offline and background timing.

Exit: all `V0.3.0-ACCEPTANCE-CRITERIA.md` release gates pass or have approved, documented exceptions.
